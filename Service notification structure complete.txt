Connexion SignalR temps réel
Le service est maintenant complet avec les 3 fonctionnalités avancées intégrées. Redis est le seul composant supplémentaire requis (déjà dans le Docker Compose) pour le SignalR backplane et le tracking des connexions.
N'hésitez pas si vous avez besoin d'un autre aspect ou d'une clarification.


Comment ces 3 entités interagissent dans le flux d'envoi
1. Événement arrive (ex: NewMessageReceivedEvent)
        │
        ▼
2. Consumer appelle NotificationDispatcher.DispatchAsync(recipientId, NotificationType.NewMessage, data)
        │
        ▼
3. Le Dispatcher charge la UserNotificationPreference pour (userId, NewMessage)
   → Résultat : Email ✅ | SMS ❌ | Push ✅ | InApp ✅
        │
        ▼
4. Pour chaque canal activé, le Dispatcher :
   a) Charge le NotificationTemplate pour (NewMessage, Email, "fr")
   b) Rend le template avec Scriban + les données
   c) Crée un NotificationRecord (channel=Email, status=Pending)
   d) Envoie via le provider (BrevoEmailSender)
   e) Marque comme Sent ou Failed
   f) Persiste le NotificationRecord en BDD
        │
        ▼
5. Résultat : 3 NotificationRecord créés en BDD
   - Id=aaa, Channel=Email, Status=Sent
   - Id=bbb, Channel=Push, Status=Sent  
   - Id=ccc, Channel=InApp, Status=Sent (+ poussé via SignalR)
