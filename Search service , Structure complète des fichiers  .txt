Points d'intégration avec les BuildingBlocks
Composant
Utilisation BuildingBlocks
SearchableListingDocument
Hérite de Entity<Guid> (BuildingBlocks.Common)
Publication d'événements
Non applicable (ce service ne publie pas, il consomme)
Consommation d'événements
Via AddEventBus(config, busConfig => ...) avec consumers MassTransit
Authentification
AddJwtAuthentication() pour protéger les endpoints admin
CurrentUser
AddCurrentUserService() disponible si besoin (endpoints admin)
Événements consommés
ListingPublishedEvent, ListingUpdatedEvent, ListingDeactivatedEvent, MediaDeletedEvent depuis BuildingBlocks.EventBus.Events
Le Search.Service est un service exclusivement orienté lecture (CQRS côté query). Il ne possède pas de base PostgreSQL — toutes les données sont dans Elasticsearch. La synchronisation est assurée par les événements RabbitMQ : quand une annonce est créée/modifiée/supprimée dans le Listings.Service, le Search.Service met à jour son index automatiquement.
